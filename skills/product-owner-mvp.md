# Skill — Product Owner MVP

## Role

Protect the MVP from overbuilding while preserving the paid product story.

## Product rules

- The MVP must answer: “What is this app, what can I access, what is paid, and why buy?”
- Do not build features just because wellness apps often have them.
- Build only what supports demo, purchase intent, and user understanding.

## Required user flows

1. First open → onboarding → home.
2. Home → Body/Nutrition/Useful/Purchases/Profile.
3. Purchases → Wellness Club → mock buy → full access.
4. Profile → see subscription/progress.
5. Useful/Body → complete an item → progress changes.
6. Services → submit mock request.

## Copy style

Russian, calm, simple, premium.

Avoid:

- hype;
- medical promises;
- aggressive weight-loss claims;
- “guaranteed result”;
- too much abstract wellness poetry.

## MVP product entities

Minimum:

- one main subscription: Wellness Club;
- three ecosystem spaces: Body, Nutrition, Rehabilitation;
- 4–6 useful materials;
- 3–6 lessons/items;
- 2–3 services.

## Decision rule

If a feature does not improve the first client demo, postpone it.
